# 发行方向、首次安装与 Root 部署

本文件记录已确认的产品边界和当前实现状态；公开发布、云端构建与实机验收分别以实际记录为准。用户操作见[首次安装与更新](../initial-install.md)。

## 已确认的两条正式路线

- **免 Root 一体 App**：集成 Android 界面、X11 和 PRoot，无需另装 Termux；精简 APK 首次运行时引导选择、下载或离线导入桌面镜像。
- **Root chroot**：与免 Root 路线共享桌面核心，提供单独的运行时适配。冷安装入口可将固定公开镜像导入新的 Root chroot，独立目录中的运行时与免 Root 一体 App 分开。

外部 Termux + Termux:X11 的免 Root PRoot 组合保留为开发、调试和迁移入口。Deck 是外部 X11 的可选悬浮输入工具，不决定 Linux 运行时，也不构成第三条正式产品路线。

## 精简 APK 与初装镜像

精简 APK 保留 App、内嵌 X11 和配套原生 PRoot；Linux 桌面脚本、Chromium/Playwright/Node 配套内容移至干净的初装镜像。首次总下载量仍包含桌面与浏览器，分开发行改善的是 APK 安装/更新体积和初装下载恢复。

源码中的首次安装页面提供版本选择、下载并安装、暂停/继续、取消与匹配版本的本地导入。下载任务和部分内容持久保存，进程退出或重启后可手动继续。下载校验长度、SHA256 和续传响应；安装检查空间，先暂存、验证，再登记完成，不覆盖已有 guest。新手引导按当前桌面和 X11 就绪状态显示，替代原先固定延迟触发的方式。

首个[干净初装镜像](https://github.com/Audrey-cn/omarchy-android/releases/tag/desktop-ubuntu24-e55030353df6)与[固定镜像目录](https://github.com/Audrey-cn/omarchy-android/releases/tag/desktop-images)已公开，随包目录已包含同一镜像。其压缩包为 999,745,976 字节、逻辑解压大小为 2,973,377,562 字节，支持 App 版本代码 64 及以上；完整 SHA256 与公开资源的 HTTP Range 206、强 ETag 已核对。

[v1.0.72-test](https://github.com/Audrey-cn/omarchy-android/releases/tag/v1.0.72-test) 已通过 K20 从 `v1.0.62-test` 同签名覆盖升级，UID、证书、13 项关键文件、旧受管文件及收据和输入法设置保持一致，真实 Hermes Agent 回归通过。隔离初装完成在线下载恢复、完整校验与登记、本地离线导入、原生桌面和 Chromium 128 验证。完整镜像在线验收使用临时内部传输代理；直连结果覆盖实际目录刷新和较小下载的跨进程续传，不据此声称直连完成整个 1 GB 镜像。详细结果和测试条件见[本轮实机记录](../reports/online-installer-k20-20261123.md)。

## 已确认的更新边界

- App、X11、PRoot 可独立于初装镜像频繁发版，继续使用同一持久签名密钥与递增版本。普通覆盖升级保留已有 guest 和个人数据；正常 App 启动不再同步受管 guest 文件、删除旧组件或重新导入 rootfs。
- Ubuntu 软件包安装和更新继续通过系统内的 APT 软件源处理。项目组件通道补充现有来源，负责自身的桌面脚本、界面及适配；第三方应用保留各自支持的更新方式。
- guest 组件由用户显式发起更新。定制图形栈和定版浏览器配套各自构建、检查与恢复。软件归属与验收条件见[更新维护清单](2026-11-23-update-maintenance.md)。
- 初装镜像低频汇总已验证的修正，目录供新用户选择一个或多个兼容版本。镜像只承担初始安装介质角色，新版本发布不触发现有用户重新下载、覆盖或迁移。
- 此轮不建设完整 rootfs 更新器、个人数据卷管理器、Ubuntu 大版本自动升级或迁移管理器。已有用户的重装与换机迁移是单独操作，不能用重新导入同名容器冒充更新。

个人数据仍存放在原有 guest 内。持续签名覆盖升级保留 Android 应用数据，不等于已经实现系统与数据物理分离，也不保证卸载、清除数据或重装后的恢复。`scripts/backup-personal.sh` 可用于个人配置备份；它不代表完整系统迁移能力。

## 发布约定

镜像从云端干净环境构建，不发布手机环境快照、个人备份或凭据。镜像附件记录来源提交、配套组件、精确大小、校验和与许可；版本化镜像 Release 设置为非 latest，目录指向固定资源，App 保留正常应用 Release 入口。

当前云端工作流已拆分精简 APK 与手动初装镜像构建。兼容目录必须使用已发布资源的真实元数据；空目录不能用占位地址、大小或校验值冒充可安装镜像。低频镜像修正与高频 App 更新独立进行。

## Root 已核对状态与后续边界

- `install.sh --mode chroot` 支持下载固定公开镜像或导入匹配的本地镜像。它要求 Root、可用 BusyBox 和外部 Termux:X11；新实例位于 `/data/omarchy-chroot`，该目录已占用时停止安装。
- 旧外部部署可继续使用 Termux 侧的 Sway 和 Chromium 桥接。新 Root guest 通过外部 Termux:X11 显示，使用项目 guest 图形运行时，启动器通过私有挂载与会话监督程序管理会话。
- 新 Root guest 的导入、桌面会话和同负载比较以[本轮 K20 记录](../reports/update-maintenance-k20-20261124.md)为准。
- Root chroot 继续运行在 Android 内核上。独立分区、独立启动属于后续单独议题。
