# Online initial installation and independent App updates

User-approved scope: publish two product routes (non-root App and Root chroot). This iteration implements the non-root small APK, resumable first installation and readiness-gated onboarding. Existing guests must survive same-key App/X11/PRoot updates without guest-file synchronization or rootfs replacement. Ubuntu software remains managed through Ubuntu's repositories. Images are versioned initial-install media, not a new whole-system update manager. Root cold-install implementation and independent Android partitions are later work.

The APK retains Android UI, embedded X11 and the paired native PRoot triplet. Linux desktop scripts, Chromium 128 / Playwright 1.46.1 / Node 24.15.0 move into the initial desktop image. Existing guest copies remain intact. No APK startup retires old managed files. Do not remove or mutate existing data for validation.

First-run UI offers an initial image version, download/install, pause/continue and local import of that selected known image. One compatible image is enough for the first release; the catalog can retain old initial versions or only the latest. Bundled catalog is the offline fallback; an owned public Release catalog can be refreshed explicitly. Download state and partial bytes survive process death/reopen/reboot. Foreground download notification and honest byte progress are required. Installation is indeterminate while extracting, not a timed fake percentage.

Downloaded images use HTTPS, immutable release URLs, expected byte length and SHA256, ABI arm64-v8a and minAppVersionCode. Resume validates the response range and entity; changed metadata cannot reuse old partial bytes. A full server response to a range request restarts cleanly. Invalid length/hash never installs. Pause preserves partial data; cancel affects only the owned download cache. Reject symlinks in owned cache paths. Persist state atomically.

Check download remainder plus unpacked size and 512 MiB headroom before installation. Verify before extraction, extract to a new private staging directory, check exit code/required files/config and adapt current Android aid records. Atomically publish only into an absent final omarchy directory. Never replace an existing guest. Register and mark complete only after successful publication; interrupted staging can be retried from the verified archive. Offline import must match the selected catalog image's size/hash. Native executable files remain in installed nativeLibraryDir, not downloaded app-writable native binaries.

Image catalog JSON schemaVersion=1, images array. Each image has: id, name, abi, minAppVersionCode, bytes, unpackedBytes, sha256, sourceSha, urls. minAppVersionCode is 64 for the first supported installer. Source SHA is 40 lowercase hex, hashes are 64 lowercase hex, IDs are [a-z0-9][a-z0-9._-]{0,79}; names are bounded plain display text. Downloaded catalog is bounded and duplicate keys rejected. Catalog URL: https://github.com/Audrey-cn/omarchy-android/releases/download/desktop-images/catalog.json. Bundled asset: initial-images.json.

Onboarding waits for the current desktop/session to be ready, not 2200ms after Activity attachment. Require a live current Sway IPC output, Waybar and a connected/laid-out X11 viewport; observe stable readiness before showing anchors. On timeout show loading/retry/skip, never prematurely mark onboarding complete. Do not modify global IME, Android security/network settings, other apps or partitions.

Cloud builds retain the existing persistent test signing key and monotonic version calculator. Publish clean initial rootfs from CI only; no phone data, credentials, device IDs, private backups or signing material in artifacts. Initial images include licenses, source identity, exact byte/hash metadata and materialized hardlinks for safe staging relocation. Image releases are non-latest; App releases remain latest. Image builds are manual/periodic, independent from frequent small APK builds.

K20 user0 validation: normal install-r over stable62, unchanged UID/certificate, selected data hashes and browser/runtime files preserved; cold launch and old browser/Agent work. Exercise new first-install path in an isolated temporary container directory or recoverable clean test package, not by wiping the user's current guest. Test interrupted/resumed HTTP transfers, invalid responses and failed installation with fixtures before the real image download. Keep only final deliverables and original private backup at the end.
